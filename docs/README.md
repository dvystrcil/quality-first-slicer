# Documentation

Project documentation is organized by purpose:

- [Product vision](product-vision.md) — goals, principles, scope, and non-goals.
- [Goals and success criteria](goals.md): measurable criteria, the first milestone, and open scope decisions.
- `architecture/` — system architecture and technical design.
- `decisions/` — architecture and product decision records.
- `development/` — contributor workflows and implementation guidance.
- `licensing/` — upstream provenance, license review, and third-party notices.
- `requirements/` — testable product and compatibility requirements.
- `testing/` — test strategy, benchmark methodology, and validation policy.

Design decisions should be recorded with their context, alternatives, consequences, and conditions that would justify revisiting them. Avoid treating an unreviewed proposal as an established project decision.
